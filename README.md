# Telemusic

Фонотека в Telegram. Файлы живут на серверах Telegram, мы храним только ссылки —
аудиобайты через наш сервер не проходят, поэтому ни хранения, ни трафика.

## Как это работает

**Мини-апп — это настройки, а не плеер.** Библиотека, плейлисты, переименование,
публикация. Играть в нём нельзя по решению, а не по недосмотру: webview не умеет
фоновое воспроизведение на iOS, и плеер внутри приложения замолкал бы при сворачивании.

**Плеер — обычная группа Telegram.** Пользователь создаёт группу, добавляет туда бота
администратором и выбирает её плеером в настройках, в разделе «Библиотека». Группа
там не одна — список собирается из всех чатов, где бот оказался вместе с человеком,
и плеер переключается в любой момент. При нажатии «Включить» бот стирает прошлый
плейлист и выкладывает новый — весь целиком. Дальше играет нативный плеер Telegram:
фон, экран блокировки, кэш, ноль трафика через нас.

**Добавление по ссылке — два шага.** Ссылка с чужой площадки сначала разбирается
на список названий, и в общем каталоге ищется то, что уже залили сюда другие: это
мгновенно и ничего не стоит. Чего не нашлось — качается yt-dlp с YouTube, отдельной
кнопкой и фоновой задачей: примерно полминуты на трек, и это **единственное место
во всём проекте, где аудиобайты идут через наш сервер**. Скачанное заливается
в канал-хранилище и дальше живёт как обычный трек — следующему человеку с той же
ссылкой качать уже не придётся.

**Каталог общий.** Треки дедуплицируются по `file_unique_id` — он одинаков для одного
файла у всех ботов. Один трек, залитый тысячей людей, хранится один раз, и «добавить
себе чужой плейлист» стоит примерно ничего.

**Группы-источники.** Бота можно добавить в группу, где уже лежит музыка, — он предложит
сделать из неё плейлист с названием группы. Связь работает **только вперёд**: всё новое
дописывается автоматически, переименование группы подхватывается. Историю перенести
пересылкой: до 100 сообщений за раз, порядок сохраняется.

### Чего Telegram не даёт

- **Истории чата бот не видит.** Метода для получения прошлых сообщений в Bot API нет.
  Бот видит только то, что приходит после его появления в чате — поэтому импорт старой
  группы возможен лишь пересылкой. Полную историю умеет забрать только MTProto-клиент
  от аккаунта пользователя, но это вход по номеру телефона и риск блокировки аккаунта.
- **Событий воспроизведения нет.** Узнать, что трек начали или дослушали, невозможно —
  ни бот, ни мини-апп таких обновлений не получают. Поэтому подсыпать треки по мере
  прослушивания нельзя; плейлист выкладывается целиком с паузами под лимит.
- **Об удалении сообщений в группе бот не узнаёт** — такого обновления не существует.
  Убрать трек из связанного плейлиста можно только вручную в настройках.
- **Теги в файле, а не в сообщении.** Название и исполнителя Telegram хранит в
  атрибутах самого файла. При отправке по `file_id` переданные `title` и `performer`
  игнорируются — переименованный трек приходил со старым именем. Поменять видимое
  в плеере можно только перезалив байты, поэтому правка имени заливает личную копию
  файла. Скачивать бот может файлы до 20 МБ: что больше, останется со старыми тегами.
- **Метаданные площадки отдают, файлы — нет.** Deezer, Apple Music и Spotify дают
  трек-листы без ключей, YouTube и SoundCloud — одно название. Самих файлов не даёт
  никто, поэтому загрузка идёт через yt-dlp с YouTube. Яндекс Музыка без OAuth-токена
  аккаунта не отдаёт даже метаданных.
- **Privacy mode.** По умолчанию в группах бот видит только команды. Чтобы забирать
  музыку из групп-источников, выключи его в @BotFather (`/setprivacy` → Disable) либо
  делай бота администратором в каждой такой группе. `npm run check` это проверяет.
- **Запустить проигрывание программно нельзя.** Мини-апп открывает группу на первом
  треке через `openTelegramLink`, дальше нужен один тап пользователя.
- **Свои сообщения бот удаляет** — в личке только первые 48 часов, в группе и канале
  с правами администратора без ограничения по времени. Отсюда требование прав.
- **Около двадцати сообщений в минуту** в одну группу. Плейлист на 60 треков
  выкладывается около трёх минут: первые пять уходят сразу, остальное фоном.

## Установка

```bash
npm install
cp .env.example .env
```

- **BOT_TOKEN** — от [@BotFather](https://t.me/BotFather)
- **STORAGE_CHANNEL_ID** — приватный канал-хранилище, бот в нём админ с правом
  публикации и удаления. Узнать id: `npm run channel-id -w @telemusic/server`
- **WEBAPP_URL** — публичный https-адрес мини-аппа

`.env` лежит в корне репозитория; сервер находит его по пути от модуля, а не от cwd.

Для загрузки по ссылке нужны `yt-dlp` и `ffmpeg`. В Docker-образе они уже стоят,
локально — `brew install yt-dlp ffmpeg`. Без них всё остальное работает, но импорт
по ссылке ограничен подбором из общего каталога: качать будет нечем.

Проверить всю цепочку — токен, канал, права бота, inline-режим, загрузчик:

```bash
npm run check -w @telemusic/server
```

## Запуск

```bash
npm run dev:server
```

```bash
npm run dev:miniapp
```

Мини-апп открывается только по https, поэтому локально нужен туннель
(`cloudflared tunnel --url http://localhost:5173`). В проде туннель не нужен:
сервер сам отдаёт собранную статику.

## Деплой на Railway

```bash
railway login
railway init
railway up
```

Первый деплой упадёт на проверке переменных — их ещё нет. Дальше:

```bash
railway volume add -m /data
railway variable set DATABASE_PATH=/data/telemusic.db
railway variable set --stdin BOT_TOKEN
railway domain
railway variable set WEBAPP_URL=https://<домен-из-предыдущей-команды>
```

Том обязателен: без него SQLite лежит на эфемерном диске и фонотека исчезает
при каждом редеплое. Сборка идёт по `Dockerfile` — Railway иначе принимает
npm workspaces за монорепу и заводит по сервису на воркспейс.

**Один бот — один поллинг.** Пока задеплоенный экземпляр работает, локальный
`npm run dev:server` даст обоим `409 Conflict`. Для отладки заводи тестового бота.

## Что умеет

**Бот**
- `/new` → название → аудио пачкой → `/done` — плейлист собирается прямо в переписке
- аудио без команды попадает в библиотеку
- ссылка без команды разбирается как импорт, недостающее качается по кнопке —
  ход загрузки правится прямо в том же сообщении
- `/player` показывает текущую группу-плеер, `/app` открывает настройки
- подключение группы-плеера при выдаче прав администратора
- inline-режим: `@бот queen` отправляет трек в любой чат

Список команд публикуется в Telegram при каждом старте (`setMyCommands`) — иначе
кнопка «≡» в переписке пуста и подсказки при вводе `/` не появляются.

**Мини-апп**
- выбор группы-плеера списком, переключение и отключение
- плейлисты: создать, переименовать, удалить, смешать все в один
- библиотека, добавление треков в плейлисты
- добавление по ссылке с другой площадки — трек, альбом или плейлист, с загрузкой
  недостающего и полосой хода
- переименование трека и исполнителя: правки личные, каталог общий, под правку
  заливается личная копия файла — иначе Telegram покажет старые теги
- получить файл трека в личку
- «где послушать» — тот же трек на других площадках
- публикация плейлиста и добавление чужого по deep link
- очистка группы-плеера вручную

Кнопка «Назад» — штатная кнопка Telegram: показанная, она встаёт в шапке на место
крестика. Своих кнопок возврата внутри нет, иначе их получается две.

**Ссылки на площадки** собираются без ключей: Apple Music и Deezer дают точные
ссылки через открытые API, для Spotify, YouTube, Яндекс Музыки и SoundCloud
отдаётся ссылка на поиск и помечается как неточная. Odesli (song.link) не
используется — его публичный API закрыт и требует ключ.

## Чего пока нет

- плейлистов Apple Music (`pl.…`) и Яндекс Музыки — им нужен ключ
- очереди загрузок: одна задача на пользователя, состояние живёт в памяти
  и теряется при перезапуске (скачанное при этом остаётся в фонотеке)
- обложек треков (`thumb_file_id` не сохраняется)
- нормализации метаданных: из тегов приходит мусор, матчинг с MusicBrainz
  заметно поднял бы качество поиска
- витрины чужих плейлистов, подписок, ленты
- восстановления `file_id` из `storage_message_id` при смене бота
- `better-sqlite3` синхронный: под нагрузкой менять на Postgres

## Структура

```
server/src/
  config.ts, env.ts        переменные окружения и понятные ошибки на старте
  db/                      схема, подключение, миграции при старте
  bot/handlers.ts          команды, приём аудио, подключение группы, inline
  services/catalog.ts      дедуп, хранилище, библиотека, поиск
  services/playlists.ts    CRUD, смешивание, публикация, клонирование
  services/player.ts       выкладка в группу, очистка, лимиты и 429
  services/drafts.ts       сбор плейлиста через /new … /done
  services/overrides.ts    личные названия поверх общего каталога
  services/links.ts        ссылки на другие площадки
  services/sessions.ts     токены для входа вне Telegram
  services/chats.ts        известные чаты и выбор группы-плеера
  services/variants.ts     перезалив файла под переименование
  services/import.ts       разбор ссылок с площадок и подбор по каталогу
  services/fetcher.ts      обёртка над yt-dlp: загрузка и состав плейлистов
  services/downloads.ts    фоновые задачи загрузки и их состояние
  api/                     проверка initData, REST для мини-аппа
  tools/                   channel-id, check
miniapp/src/
  App.tsx                  настройки: плейлисты, библиотека, редактор трека
  api.ts, telegram.ts      клиент и обвязка WebApp SDK
```

## Про юридическую сторону

Личная и компанейская фонотека — обычный кейс. Публичная витрина, где чужие люди
слушают залитое другими, делает проект сервисом распространения фонограмм. Уязвимы
там домен, хостинг и платёжный провайдер — то есть твоя инфраструктура, а не Telegram.

Загрузка через yt-dlp меняет картину сильнее всего остального: это уже не хранение
присланного пользователями, а получение фонограмм с площадок силами сервиса, причём
с твоего IP и в нарушение их условий использования. Отключается одной переменной —
достаточно убрать `yt-dlp` из образа или указать несуществующий `YTDLP_PATH`:
разбор ссылок и подбор по каталогу продолжат работать.
