# Telemusic

Фонотека и плеер поверх Telegram. Файлы живут на серверах Telegram, мы храним только ссылки —
аудиобайты через наш сервер не проходят никогда, поэтому ни хранения, ни трафика.

## Как это работает

1. Пользователь кидает боту аудио → бот копирует его в приватный **канал-хранилище** платформы
   и записывает метаданные в БД. Дедуп по `file_unique_id`: один и тот же файл, залитый тысячей
   людей, хранится один раз, и из этого сам собой собирается общий каталог.
2. В мини-аппе собираются плейлисты. Плейлист — это строки в БД, а не файлы, поэтому
   «добавить себе чужой плейлист» стоит примерно ничего.
3. Кнопка «Слушать» просит сервер выложить треки в личный канал пользователя и возвращает ссылку
   на первый трек. Мини-апп открывает её через `openTelegramLink`, пользователь делает **один тап** —
   дальше нативный плеер Telegram играет подряд, с фоном, экраном блокировки и кэшем.

Запустить воспроизведение программно нельзя: такого API у Telegram нет ни у ботов, ни у мини-аппов.
Поэтому кнопка называется «Слушать в Telegram», а не «Play» — это честное описание происходящего.

## Установка

```bash
npm install
cp .env.example .env
```

Заполни `.env`:

- **BOT_TOKEN** — от [@BotFather](https://t.me/BotFather)
- **STORAGE_CHANNEL_ID** — приватный канал-хранилище. Создай канал, добавь бота админом
  с правом публикации и удаления, узнай id (вида `-1001234567890`)
- **WEBAPP_URL** — публичный https-адрес мини-аппа

`.env` лежит в корне репозитория; сервер находит его по пути от модуля, а не от cwd,
поэтому запуск через npm workspaces из `server/` работает без сюрпризов.

Узнать id канала:

```bash
npm run channel-id -w @telemusic/server
```

Скрипт поднимает бота и печатает id любого канала, в котором тот админ — достаточно
опубликовать там любое сообщение.

Мини-апп открывается только по https, поэтому для локальной разработки нужен туннель:

```bash
cloudflared tunnel --url http://localhost:5173
```

Полученный адрес пропиши в `WEBAPP_URL` и в BotFather: `/newapp` → путь `app`, чтобы работал
deep link `t.me/<bot>/app?startapp=<slug>`. Там же включи inline-режим (`/setinline`).

## Запуск

```bash
npm run dev:server
```

```bash
npm run dev:miniapp
```

Vite проксирует `/api` на сервер, так что фронт и API живут на одном origin.

Для продакшена `npm run build` — сервер отдаёт собранный мини-апп из `miniapp/dist` сам.

## Что уже есть

- приём аудио в личке и в подключённом канале, дедуп по `file_unique_id`
- копирование в канал-хранилище (по `file_id`, без скачивания файла)
- личная библиотека, плейлисты, добавление и удаление треков
- выкладка плейлиста в канал пользователя: первые 8 треков синхронно, хвост фоном
  (Telegram пропускает примерно сообщение в секунду в один чат)
- публикация плейлиста и клонирование чужого по deep link
- inline-режим: `@бот queen` отправляет трек в любой чат
- авторизация мини-аппа проверкой подписи `initData`

## Чего пока нет

- обложки треков (`thumb_file_id` не сохраняется)
- нормализация метаданных — из тегов приходит мусор, матчинг с MusicBrainz заметно улучшит поиск
- витрина чужих плейлистов, подписки, лента
- восстановление `file_id` из `storage_message_id` при смене бота
- `better-sqlite3` синхронный: под нагрузкой заменить на Postgres

## Структура

```
server/
  src/config.ts            переменные окружения
  src/db/schema.ts         таблицы (drizzle)
  src/db/index.ts          подключение + CREATE TABLE при старте
  src/bot/bot.ts           инстанс grammY
  src/bot/handlers.ts      /start, приём аудио, подключение канала, inline
  src/services/catalog.ts  дедуп, хранилище, библиотека, поиск
  src/services/playlists.ts CRUD, публикация, клонирование
  src/services/player.ts   выкладка плейлиста и ссылка на первый трек
  src/api/auth.ts          проверка initData
  src/api/routes.ts        REST для мини-аппа
miniapp/
  src/App.tsx              библиотека, плейлисты, шаринг
  src/api.ts               клиент
  src/telegram.ts          WebApp SDK
```

## Про юридическую сторону

Личная и компанейская фонотека — обычный кейс. Публичная витрина, где чужие люди слушают
залитое другими, делает проект сервисом распространения фонограмм. Уязвимы там домен, хостинг
и платёжный провайдер — то есть твоя инфраструктура, а не Telegram. Функциональность публикации
уже в коде, но включать витрину и рост вокруг неё — осознанное решение с последствиями.
